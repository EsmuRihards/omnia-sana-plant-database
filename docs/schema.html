how the numbers are made

Evidence scoring & publish gating

Scores are computed at build time, never hand-typed. Same data → same number, and every score is auditable from its reference_ids. Two ladders exist and must never be swapped: one grades whether a plant works in a human body, the other whether an extraction reproduces on a bench.

① Clinical evidence — the 1–10 score

Powers the Symptom-to-Plant Lookup, plant-page indication dots, comparison & monograph. Lives on each indication. Rendered as 5 dots by os-scoring.php.

base = tier of the STRONGEST cited source
bonus = +3 if ≥5 human sources · +2 if 3–4 · +1 if 2 · else +0
score = clamp(base + bonus, 1, 10)
Volume of weak evidence never lifts the floor. Ten in-vitro studies still score 2; traditional-only sources score 1. A score is only as specific as that indication's own reference_ids — pinning a whole bibliography to every indication hands each one the maximum and makes the number meaningless.

② Extraction evidence — the practice bands

Powers the Tincture Calculator (practice.v1.json). Grades reproducibility of a (solvent, temp, time, ratio, yield) finding. This ladder is the inverse of the clinical one.

bands: ≥8 established · ≥5 supported · ≥2 provisional · <2 insufficient
A review is the top clinical tier and scores 0 here — it reports no single measured tuple. An RCT has no tier here at all. This feed deliberately never emits a key named evidence, so a renderer built for the clinical dots shows nothing rather than the wrong thing: ten dots must not read as "strong" when it would only mean "three labs agree on a solvent percentage."

The three gates — what actually reaches the public

validate.pyhard gate · exit 0
Every cited REF-XXXX must resolve to a BibTeX entry and every vocab id must exist. Exit 1 blocks the commit. Narrower than it looks: it does not check the JSON schema, study_type, or per-claim status — a green run means references and vocabulary resolve, not that the data is correct.
D8 · sourced-onlybuild.py filter
"Nothing unsourced publishes." Any preparations/dosage entry without reference_ids is withheld from plants.json (≈244 preparations & 53 dosages at measurement). Nothing is deleted — the YAML keeps every word; an entry reappears the moment it earns a citation.
approved-onlysafety lists
The three safety lists — drug_class_interactions, pairings, dangerous_lookalikes — use a separate draft → approved lifecycle. Public tools serve approved records only; a Claude-drafted safety claim never ships without human medical sign-off.
